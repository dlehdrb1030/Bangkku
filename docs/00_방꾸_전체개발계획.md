## 1. 프로젝트 개요

### 한 줄 정의
이사할 집의 평면도를 3D 공간으로 만들고, 가우시안 스플라팅(3DGS)으로 만든 가구를 VR에서 직접 배치하며 **겹침·간격·공간감**을 미리 확인하는 시스템.

### 프로젝트 방향성
실제 치수 기반의 정확한 판정과 VR의 공간감 체험을 결합해, 가구 배치를 미리 검증하고 결정할 수 있는 시스템을 만든다.

### 핵심 설계 원칙
1. **박스는 판정, 3DGS는 외관**
   충돌·간격 판정은 줄자로 잰 **실측 박스**로만 한다. 3DGS는 실측 박스에 맞춰 크기만 보정하는 겉모습이다.
2. **구조물은 메쉬, 가구는 3DGS**
   벽·바닥·천장은 메쉬(가볍고 재질 교체 쉬움), 가구는 3DGS(사실감).
3. **판정과 체험의 분리**
   "들어가나"는 숫자로, "답답한가"는 VR 공간감으로 판단한다.
4. **항상 대체 경로를 둔다**
   3DGS가 안 되면 메쉬나 박스로, VR이 안 되면 데스크톱 모드로 동작해야 한다.

## 2. 개발 범위

### 필수 (MVP)
- [ ] 평면도 JSON → 벽·문·창·바닥·천장 자동 생성
- [ ] 3DGS 가구 로드 + 실측 치수 기반 크기 보정
- [ ] 이동 (VR 텔레포트 / 데스크톱 WASD)
- [ ] 가구 잡기·이동·회전(Y축만)·바닥 스냅
- [ ] 충돌 판정 (가구-벽, 가구-가구, 가구-고정설비) + 색상 경고
- [ ] 선택한 가구와 가장 가까운 벽·가구까지 거리 표시
- [ ] **데스크톱 모드** (마우스로 배치, VR 장비 없이 테스트) ← 맥 개발 환경 때문에 필수

### 권장
- [ ] 신규 가구를 치수 입력으로 박스 생성
- [ ] 치수 신뢰도 라벨 (실측 / 도면 / 추정)
- [ ] 배치 상태 저장·불러오기

### 선택
- [ ] 문 폭 대비 가구 반입 검사

### 제외
방 전체 스캔 후 가구 자동 분리, 도면 자동 인식, 재조명(relighting), Quest 단독 실행에서의 3DGS 지원, 상용화.

## 5. 공통 규칙 (가장 중요)

### 좌표·단위
| 항목 | 규칙 |
|---|---|
| Unity 단위 | **1 unit = 1m** |
| JSON 단위 | **mm (정수)** |
| 변환 | `Units.MM_TO_M = 0.001f`, 코드에서 숫자 `0.001`을 직접 쓰지 않음 |
| 축 | Y-up. 평면도 X → Unity X, 평면도 Y → Unity **-Z** (Top 뷰가 평면도 이미지와 같은 모양. `Units.PlanToWorld`만 사용) |
| 평면도 원점 | 평면도 좌상단 외벽 모서리 = (0, 0) |
| 가구 원점 | **바닥면 중앙** |
| 가구 정면 | **+Z** |
| 가구 회전 | **Y축만**. 스냅 기본 90°, 미세 조정 15° |

### Layer / Tag
| Layer | 대상 |
|---|---|
| `Wall` | 벽 조각 |
| `Floor` | 바닥 (텔레포트 영역) |
| `Furniture` | 배치 가능한 가구 |
| `Fixture` | 고정 설비 (주방, 변기 등, 이동 불가) |

### 이름 규칙
- 에셋 ID: 소문자_번호 (`sofa_01`, `oneroom_01`)
- C# 클래스: PascalCase, 파일명 = 클래스명
- 네임스페이스: `Bangkku.Core`, `Bangkku.FloorPlan`, `Bangkku.Furniture`, `Bangkku.Placement`, `Bangkku.Input`, `Bangkku.UI`, `Bangkku.IO`

### 치수 신뢰도
| 값 | 의미 | 판정 여유값 |
|---|---|---|
| `measured` | 줄자 실측 | 10mm |
| `drawing` | 도면·상품 상세 치수 | 30mm |
| `estimated` | 표준값으로 추정 | 100mm |

## 7. 데이터 형식

### 7.1 평면도 `floorplan.json` (팀장 관리)
```json
{
  "name": "oneroom_01",
  "unit": "mm",
  "ceilingHeight": { "value": 2400, "confidence": "estimated" },
  "defaultWallThickness": 200,
  "walls": [
    { "id": "w0", "start": [0, 0], "end": [4240, 0], "thickness": 200, "confidence": "drawing" }
  ],
  "openings": [
    { "id": "win0", "wallId": "w0", "type": "window", "offset": 1860, "width": 1600, "sill": 900, "head": 2100 },
    { "id": "door0", "wallId": "w5", "type": "door", "offset": 300, "width": 800, "sill": 0, "head": 2100 }
  ],
  "floors": [
    { "id": "f0", "material": "wood", "polygon": [[200,200],[4040,200],[4040,2900],[200,2900]] }
  ],
  "fixtures": [
    { "id": "kitchen", "type": "counter", "position": [850, 1770], "size": [1300, 600, 900], "rotation": 0 }
  ]
}
```
- `start`, `end`: 벽 **중심선** 좌표
- `offset`: 벽 `start`에서 개구부 시작까지 거리
- `fixtures.position`: 바닥면 중앙 (mm), `size`: [W, D, H]

### 7.2 가구 카탈로그 `catalog.json` (팀원 관리)
```json
{
  "items": [
    {
      "id": "sofa_01",
      "name": "2인 소파",
      "source": "scan",
      "prefab": "Prefabs/Furniture/sofa_01",
      "size": { "w": 1500, "d": 800, "h": 800 },
      "sizeConfidence": "measured",
      "splatMeasuredSize": { "w": 1530, "d": 820, "h": 790 },
      "fitError": 0.021,
      "unscannedFaces": ["back"]
    },
    {
      "id": "bed_new",
      "name": "구매 예정 침대",
      "source": "box",
      "size": { "w": 1100, "d": 2000, "h": 450 },
      "sizeConfidence": "drawing",
      "color": "#7B9CC4"
    }
  ]
}
```
- `source`: `scan`(3DGS) / `mesh`(대체 메쉬) / `box`(치수만)
- `size`: **판정 기준 치수** (W=X, D=Z, H=Y)

### 7.3 배치 저장 `layout.json` (팀장 관리)
```json
{
  "floorplan": "oneroom_01",
  "placements": [
    { "itemId": "sofa_01", "position": [2280, 2470], "rotationY": 0 },
    {
      "itemId": "box_01", "position": [3270, 6900], "rotationY": 90,
      "item": { "id": "box_01", "name": "침대", "source": "box", "size": { "w": 1100, "d": 2000, "h": 450 }, "sizeConfidence": "drawing", "color": "#7B9CC4" }
    }
  ]
}
```
- 파일: `persistentDataPath/layouts/<floorplan>.json` (평면도마다 하나)
- `position`: 가구 바닥면 중앙 (평면도 mm), `rotationY`: 도
- `item` (선택): **박스 가구(`source: box`)만**. 가구 메뉴로 추가한 새 박스는 `catalog.json`에 없어서 이름·치수·신뢰도·색을 함께 저장한다 (형식은 7.2 카탈로그 항목과 같음). 카탈로그 가구는 이 칸이 없고 `itemId`로 `catalog.json`에서 찾는다

## 8. 두 사람 사이의 약속 (인터페이스)

### 8.1 가구 프리팹 구조
```
FurnitureItem (루트)
│  Layer = Furniture
│  Rigidbody (isKinematic = true, useGravity = false)
│  FurnitureItem.cs           ← 팀장 작성
│  XRGrabInteractable         ← 팀장이 베이스 프리팹에 설정
├── Visual                    ← 팀원: 3DGS 렌더러 / 메쉬 / 박스
├── Collider                  ← 팀원: BoxCollider, size = 실측 치수(m), center.y = 높이/2
├── Outline                   ← 팀장: 박스 윤곽선 (LineRenderer)
└── LabelAnchor               ← 팀원: 박스 윗면 중앙 위치
```
- 팀원은 **`FurnitureItem_Base.prefab`의 Prefab Variant**로 가구 프리팹을 만든다. 그래야 팀장이 베이스를 고치면 모든 가구에 반영된다.

### 8.2 `FurnitureItem.cs` 공개 API (팀장이 1주차에 먼저 만듦)
```csharp
namespace Bangkku.Placement {
  public enum PlacementState { Free, Tight, Overlap }

  public class FurnitureItem : MonoBehaviour {
    public string ItemId;                 // catalog id
    public Vector3 SizeMeters;            // 실측 W, H, D (m)
    public Confidence SizeConfidence;
    public BoxCollider BoxCollider;       // 판정용
    public Transform LabelAnchor;
    public PlacementState State { get; }
    public float MinGapMeters { get; }    // 가장 가까운 벽·가구까지
    public void Init(CatalogItem data);   // FurnitureFactory가 호출
  }
}
```
- 팀원의 `FurnitureFactory`는 `catalog.json`을 읽어 프리팹을 생성하고 `Init()`만 호출한다.
- 판정·상태 표시는 팀장 쪽 코드가 담당한다.

### 8.3 주고받는 것
| 시점 | 팀장 → 팀원 | 팀원 → 팀장 |
|---|---|---|
| 1주차 | 저장소, 폴더 구조, `Core/`, `Data/`, `FurnitureItem_Base.prefab` | 플러그인 설치 결과, 가구 1개 프리팹 |
| 2주차 | 평면도 씬, 잡기 동작하는 베이스 프리팹 | 가구 3~5개 프리팹, `catalog.json`, `FurnitureFactory` |
| 3주차 | 판정·라벨 동작 버전 | 성능 측정표, 최적화된 프리팹 |
| 4주차 | 통합 빌드 | 정확도 평가표, 시연 영상 |

## 9. 협업 방법

### Git 설정 (1일 차, 팀장이 만들고 팀원이 확인)
- Unity 공식 `.gitignore` (`Library/`, `Temp/`, `Logs/`, `UserSettings/`, `Build/`, `obj/` 제외)
- `Project Settings > Editor`
  - Version Control: **Visible Meta Files**
  - Asset Serialization: **Force Text**
- `.meta` 파일은 **항상 함께 커밋**
- Git LFS (`.gitattributes`):
  ```
  *.ply filter=lfs diff=lfs merge=lfs -text
  *.splat filter=lfs diff=lfs merge=lfs -text
  *.glb filter=lfs diff=lfs merge=lfs -text
  *.fbx filter=lfs diff=lfs merge=lfs -text
  *.png filter=lfs diff=lfs merge=lfs -text
  *.jpg filter=lfs diff=lfs merge=lfs -text
  *.psd filter=lfs diff=lfs merge=lfs -text
  ```
- (선택) UnityYAMLMerge를 Git merge tool로 등록

### 큰 파일
- **촬영 원본 영상, 원본 .ply** → 구글 드라이브 `방꾸/raw/` (Git 금지)
- **정리된 스플랫 에셋** → 용량이 작으면 Git LFS, 크면 `Assets/_Project/Splats/`를 `.gitignore`에 넣고 드라이브 `방꾸/splats/`로 공유. 파일명에 버전 표기 (`sofa_01_v2`)
- GitHub LFS 무료 용량을 넘기지 않도록 매주 확인

### 브랜치
```
main      ← 항상 실행 가능 (병합 시점은 두 사람이 정함)
dev       ← 통합
feature/<담당>-<기능>   예) feature/dk-floorplan-walls, feature/hj-splat-sofa
```

### 하루 흐름
1. 시작 전 `dev` pull → 내 브랜치에 반영
2. 작게 자주 커밋 (`feat:`, `fix:`, `refactor:`, `docs:`)
3. 기능 단위로 Pull Request → 상대가 간단히 확인 후 `dev` 병합
4. 하루 한 줄 공유: 한 일 / 할 일 / 막힌 것

### 충돌 방지 규칙
- **같은 씬을 동시에 수정하지 않는다.** 결과물은 프리팹으로 넘긴다.
- `Core/`, `Data/`, `ProjectSettings/`, `Packages/` 를 고칠 때는 **먼저 말하고** 고친다.
- 패키지 추가는 한 사람이 하고 바로 커밋한다.

### 통합 (Windows VR PC)
1. 두 사람 브랜치를 `dev`에 병합
2. `Main_VR.unity`를 PC VR로 실행
3. 이번 주 마일스톤 확인, 성능 기록
4. 문제없으면 `dev` → `main`

## 13. Claude Code 사용 규칙
- 각자 자기 가이드 문서와 이 문서를 Claude Code 프로젝트에 함께 넣는다.
- Claude Code에게 작업을 맡길 때는 **이 문서의 5장(규칙), 6장(폴더·소유자), 7~8장(데이터·인터페이스)을 지키라고** 명시한다.
- 상대 소유 파일은 Claude Code로도 수정하지 않는다. 필요하면 상대에게 요청한다.
- Unity 씬·프리팹(YAML)은 Claude Code로 직접 편집하지 말고, 스크립트와 JSON 위주로 맡긴다. 씬 구성은 에디터에서 사람이 한다.
- 생성된 코드는 에디터에서 실행해 보고 커밋한다.
