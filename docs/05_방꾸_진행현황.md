**평면도 데이터 메모 (`oneroom_01.json`)**
- 원점 (0, 0) = 좌상단 외벽 중심선 교차점 (치수선 기준). 이미지 축척 약 14.62 mm/px
- 세로 치수(640 / 2100 / 3020 / 1100)는 그림과 일치. 가로 치수 중 `1730` 눈금선이 그림에서 욕실 벽(약 1990)에 잘못 그려져 있음 → 욕실 왼쪽 벽은 그림에서 잰 1990, 신발장 오른쪽 벽은 표기값 2480 사용
- 발코니 바깥 벽은 표기 총길이 6860이 바깥면이라 중심선을 6800으로 둠
- 그림에서 잰 값은 `estimated`, 치수 표기와 맞는 값은 `drawing`. 실측하면 2주차 "평면도 보정"에서 고침
- 바깥 회색 영역(좌상단, 우상단 PS, 발코니 아래)은 이 집이 아니라서 바닥을 만들지 않음
- 치수 기준: `oneroom_01.dimensions.json` (도면 치수 9개 + 참고 측정 3개). 줄자로 실측하면 참고 항목에 `expectedMm`을 적어 실측 대비 오차(±2cm)를 확인

## 6. 작업 방식 메모 (Claude Code와 작업할 때)

- 요청할 때 **"팀장 작업"** 이라고 적으면 `01` 가이드를 먼저 읽고 진행합니다 (`CLAUDE.md`).
- Claude Code가 하는 것: C# 스크립트, JSON, 에디터 확장 스크립트, 문서. 하지 않는 것: `.unity`·`.prefab`·`.asset`·`ProjectSettings/`·`manifest.json` 직접 편집 (사람이 에디터에서, 또는 메뉴 하나로 적용하는 에디터 스크립트로).
- `Core/`, `Data/`를 바꿀 때는 설계를 먼저 설명하고 확인을 받은 뒤 작성합니다.
- 컴파일 확인: 에디터가 열려 있어도 Unity에 포함된 컴파일러(Roslyn)로 프로젝트와 같은 설정으로 미리 컴파일해 봅니다. 그 뒤 에디터 Console에서 한 번 더 확인하고 커밋합니다.
- 브랜치: `dev`에서 `feature/dk-<기능>`. 리뷰 대기 중이면 이전 작업 브랜치 위에 쌓습니다.
  - 쌓은 PR을 병합할 때는 **다음 PR의 base를 먼저 `dev`로 바꾼 뒤** 앞 브랜치를 삭제합니다. 브랜치를 먼저 지우면 다음 PR이 자동으로 닫힙니다 (실제로 겪음). 강제 push(`--force`)도 PR을 닫으므로 이미 올린 브랜치의 커밋 기록은 고치지 않습니다.
- Unity가 스스로 바꾼 `ProjectSettings/` 변경은 작업 커밋과 **분리**해서 커밋합니다.
