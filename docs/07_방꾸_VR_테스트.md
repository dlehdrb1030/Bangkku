>
> | 단계 | 내용 | 커밋 |
> |---|---|---|
> | 2. VR 연결 | Meta Horizon Link, OpenXR 런타임, Unity XR 설정 확인 | 없음 |
> | 2-A. VR 기본 | 3DGS 없이 이동·잡기·손목 메뉴 | 없음 |

> 시작 조건: 06 문서 **1-A 통과**. 2-B는 06 문서 **1-B 상태(플러그인·`StreamingAssets`·스플랫 오브젝트)가 남아 있어야** 합니다.
> 기준: Unity **6000.3.27f2**, XRI 3.3.2, OpenXR 1.16.1, 3DGS 플러그인 v2.0.0 (2026-11-10 기준)

## 2. VR 연결

### 2.1 헤드셋 준비

- Quest 펌웨어를 최신으로 업데이트 (설정 > 일반 > 소프트웨어 업데이트)
- 헤드셋과 PC 앱에 **같은 Meta 계정**으로 로그인
- 컨트롤러 배터리 확인
- Link만 쓸 때는 헤드셋 개발자 모드가 필요 없습니다 (APK 설치할 때만 필요)

### 2.2 PC 앱 (Meta Horizon Link)

1. meta.com에서 **Meta Horizon Link** PC 앱 설치 후 로그인
2. 앱 왼쪽 **Devices** > **Add Headset** → 쓰는 Quest 선택
3. 연결 방식
   - **Link (케이블)**: USB-C 3 케이블. 앱이 제안하는 **연결 테스트**를 실행해 속도를 확인 (USB 2로 잡히면 다른 포트나 케이블)
   - **Air Link (무선)**: PC가 유선 LAN, 공유기 5GHz/6GHz. 끊기거나 지연되면 케이블로 바꿈
4. Devices > 헤드셋 > **Graphics Preferences**
   - Refresh Rate: **72Hz** (성능 기준이 72fps)
   - Render Resolution: 기본값 (바꿨다면 기록)

### 2.3 OpenXR 런타임

1. Link 앱 > **Settings > General**
2. **OpenXR Runtime** 항목에서 **Set Meta Horizon Link as active** (이미 활성이면 버튼이 없음)
3. SteamVR이 설치된 PC면 SteamVR이 런타임을 가져가지 않았는지 확인 (SteamVR 설정 > OpenXR에서 "현재 런타임"이 Meta인지)

### 2.4 헤드셋에서 Link 켜기

1. 케이블 연결 (또는 같은 네트워크)
2. 헤드셋 **빠른 설정 > Link** (또는 Quest Link) > 실행
3. 회색 Link 홈 공간이 보이면 연결됨
4. 헤드셋을 쓴 채로 PC 화면을 보려면 Link 홈의 **데스크톱** 버튼 사용

### 2.5 Unity 설정 확인 (이미 저장소에 들어 있음, 바꾸지 않음)

Edit > Project Settings > **XR Plug-in Management** > **Windows** 탭 (모니터 아이콘)

| 항목 | 값 |
|---|---|
| Initialize XR on Startup | ✅ |
| Plug-in Providers | **OpenXR** ✅ |
| OpenXR > Enabled Interaction Profiles | Oculus Touch Controller Profile, Meta Quest Touch Pro Controller Profile, Meta Quest Touch Plus Controller Profile |
| OpenXR > Render Mode | **Single Pass Instanced** (2-B에서 비교할 때만 바꿈) |
| Project Validation | 경고·오류 없음 (있으면 내용 기록. **Fix All은 누르지 않고** 기록만. 설정이 바뀌면 커밋 대상이 됨) |

## 2-A. VR 기본 (3DGS 없이)

> 06 문서 1-B를 이미 했다면, 스플랫 오브젝트(`Splat_Chair`, `Splat_Desk`)의 체크를 꺼서 숨긴 채 진행합니다.

### 2-A.1 실행

1. Link가 연결된 상태(헤드셋에 Link 홈이 보임)에서 Unity의 `Main_VR`을 엽니다
2. Play → 헤드셋을 씀
3. Console에 `[방꾸] 실행 모드: VR (헤드셋) ...`이 나오면 정상
   - `데스크톱`으로 나오면: Link가 끊겼거나 OpenXR 런타임이 Meta가 아님 (2.3, 2.4). Play를 멈추고 Link를 다시 켠 뒤 Play
4. Game 뷰에는 한쪽 눈 화면이 보입니다 (PC 화면은 참고용)

### 2-A.2 조작

XR Origin은 XRI **Starter Assets** 기본 설정입니다. 아래가 실제와 다르면 실제 동작을 기록합니다.

| 입력 | 동작 |
|---|---|
| 왼쪽 스틱 | 걷기 이동 |
| 오른쪽 스틱 좌우 | 시점 회전 |
| 오른쪽 스틱 앞으로 밀기 → 놓기 | 텔레포트 (바닥을 가리켜야 함) |
| **그립** (중지 버튼) | 가구 잡기. 손이 가구에 닿아 있으면 근거리, 레이로 가리키면 원거리 |
| 잡은 채 그 손 스틱 좌우 | 가구 90° 회전 |
| 잡은 채 **트리거** + 스틱 좌우 | 가구 15° 회전 |
| 왼손 위 패널 | 손목 메뉴. **오른손 레이 + 트리거**로 누름 |

### 2-A.3 확인

| 항목 | 정상 |
|---|---|
| 시작 위치 | 현관문 안쪽에서 방 안쪽을 봄 |
| 눈높이 | **실제 키에 맞음** (시뮬레이터용 1.6m 보정은 헤드셋에서는 적용되지 않아야 정상) |
| 머리 추적 | 끊김·흔들림 없음, 바닥이 실제 바닥 높이 |
| 컨트롤러 | 양손 모델이 보이고 손을 따라옴 |
| 텔레포트 | 방·현관·욕실·발코니 바닥으로 이동. 벽·천장으로는 안 됨 |
| 현관문 | 걸어서 나가려 하면 **문에 막힘** |
| 떨어짐 복구 | (일부러 재현하지 않아도 됨) 바닥 밖으로 떨어지면 시작 위치로 돌아옴 |
| 근거리 잡기 | 손을 박스 가구에 대고 그립 → 손을 따라 수평 이동, 바닥에 붙어 있음 |
| 원거리 잡기 | 레이로 가구를 가리키고 그립 → 레이 따라 이동 |
| 스냅·회전 | 10mm 격자, 벽 30mm 안에서 붙음, 90°/15° 회전 |
| 잡는 동안 | 시점 회전·이동·텔레포트가 잠김 (스틱이 회전에 쓰임) |
| 판정 색 | 여유 초록 / 좁음 노랑 / 겹침 빨강 윤곽선이 잘 보임 |
| 거리 라벨·신뢰도 라벨 | 글자가 읽히고 항상 나를 향함, 한글 깨짐 없음 |
| 손목 메뉴 | 침대·책상 버튼 → 치수 채워짐, ±10/±100, 추가(앞 바닥에 생김), 이전·다음 선택, 삭제, 저장·불러오기, 접기 |
| 편안함 | 멀미·끊김 정도 (주관, 1~5점으로 기록) |

### 2-A.4 exe로 VR 실행

1. 06 문서 1-A.6과 같은 방법으로 빌드 (이미 했으면 그 exe를 씀)
2. Link가 연결된 상태에서 `방꾸.exe` 실행 → 헤드셋에 VR로 켜짐
   - Link 없이 실행하면 데스크톱 모드 (같은 exe 하나로 두 모드)
3. 2-A.3의 주요 항목(시작 위치, 잡기, 손목 메뉴)을 다시 확인

### 2-A 통과 기준

- [ ] VR 모드로 켜짐, Console 오류 없음
- [ ] 이동·텔레포트·현관문 막힘
- [ ] 근거리·원거리 잡기, 스냅·회전
- [ ] 판정 색, 라벨, 손목 메뉴
- [ ] exe에서도 VR로 켜짐

## 2-B. VR + 3DGS (마일스톤 1: 3DGS 가구가 PC VR에서 보임)

### 2-B.1 준비

- 06 문서 1-B 상태: 플러그인 설치, `PC_Renderer`에 Gaussian Splat URP Feature, `Assets/StreamingAssets/`에 `.ply` 2개
- Unity를 껐다 켰다면 `Splat_Chair`·`Splat_Desk`는 저장하지 않아서 없어졌을 수 있습니다. 06 문서 **1-B.4의 3~7번**을 다시 합니다
- 2-A에서 껐던 스플랫 오브젝트를 다시 켭니다

### 2-B.2 표시 확인 (Single Pass Instanced, 기본값)

Play → 헤드셋에서 의자·책상 쪽으로 이동해서 봅니다.

| 항목 | 정상 | 아니면 |
|---|---|---|
| 양쪽 눈 | 한쪽 눈씩 번갈아 감아도 **양쪽 모두** 보임 | 2-B.3 (Multi Pass) |
| 겹침 | 두 눈 화면이 같은 자리에 맞아 하나로 보임 (겹쳐 보이거나 어지럽지 않음) | 2-B.3 |
| 위아래·방향 | 뒤집히지 않음, 다리가 바닥 쪽 | 06 문서 1-B.5 |
| 머리를 움직일 때 | 스플랫이 흔들리거나 늦게 따라오지 않음, 깜빡이지 않음 | 기록 |
| 크기 느낌 | 박스 가구·벽과 비교해 어색한 정도 (아직 실측 보정 전이라 참고만) | 기록 |
| 가까이 갈 때 | 30cm 안까지 다가가도 크게 깨지지 않음 | 기록 |

### 2-B.3 Render Mode 비교 (필요할 때 / 시간이 되면)

플러그인 문서는 XR에 **Multi Pass**를 권장합니다. 2-B.2가 정상이어도 FPS 비교를 위해 한 번 해 보면 좋습니다.

1. Play를 멈춤
2. Project Settings > XR Plug-in Management > **OpenXR** > Windows 탭 > **Render Mode** = **Multi-pass**
3. Play → 2-B.2를 다시 확인, 2-B.4의 FPS도 같이 잼
4. 끝나면 **Single Pass Instanced로 되돌림** (이 설정은 `Assets/XR/Settings/`에 저장되므로, 바꿔야 한다면 맥에서 정식으로 바꾸고 03 문서를 고침)

### 2-B.4 FPS 측정

> 에디터는 에디터 자체 부하가 있어 낮게 나옵니다. **exe로 재는 값을 기준**으로 합니다. 목표는 **72fps 유지** (Refresh Rate 72Hz).

**재는 도구** (둘 중 하나)
- **Oculus Debug Tool**: Link 앱 설치 폴더의 `Support\oculus-diagnostics\OculusDebugTool.exe` (기본 `C:\Program Files\Oculus\Support\oculus-diagnostics\`) → **Performance HUD** = **Performance Summary** → 헤드셋 화면에 앱 FPS와 놓친 프레임(Dropped Frames)이 보임
- **Unity Profiler**: Build Profiles에서 **Development Build** + **Autoconnect Profiler**를 켜고 빌드 → exe 실행 시 Unity Window > Analysis > Profiler에 연결됨 (Development Build는 조금 느리므로 참고값)

**측정 순서** (각 상태에서 30초 동안 방 안을 둘러보며 평균·최저를 기록)
1. 스플랫 없음 (스플랫 오브젝트 끄고 빌드)
2. 의자 1개 (약 6.3만)
3. 의자 + 책상 (약 19만)
4. (여유 있으면) `Splat_Chair`를 Ctrl+D로 복제해 **5개 / 10개** 놓고 측정 → 마일스톤 3(가구 10개 72fps)의 첫 감 (10개면 약 63만)

> 스플랫 개수를 바꿀 때마다 exe를 다시 빌드해야 합니다. 시간이 부족하면 1~3만 하고, 4는 에디터 값으로 대신 기록합니다 (에디터 값이라고 표시).

### 2-B 통과 기준 (마일스톤 1)

- [ ] PC VR에서 3DGS 가구가 **양쪽 눈에 맞게** 보임
- [ ] 스플랫 2개 상태에서 72fps 유지 (또는 측정값 기록)
- [ ] 어떤 Render Mode에서 됐는지 기록

### 2-B가 안 될 때 (전체개발계획 11장 순서)

1. **Render Mode = Multi-pass**로 다시 확인 (2-B.3)
2. 플러그인 **v1.x(에셋 방식)** 로 바꿔 확인: Package Manager에서 2.0.0을 Remove → GitHub Releases에서 v1.x 최신 태그로 다시 설치 (`...?path=/package#<태그>`) → `Tools > Gaussian Splats > Create GaussianSplatAsset`으로 `.ply`를 에셋으로 변환 → `GaussianSplatRenderer`의 Asset 칸에 연결 (04 문서 4.7 비교표)
3. 그래도 안 되면 3DGS는 데스크톱 시연만, VR은 **메쉬(.glb) 가구**로 전환 결정 (팀원과)

## 3. 끝나고 할 일

### 3.1 되돌리기 (이 PC에서 커밋하지 않음)

1. Unity를 닫음 (씬 저장을 물으면 **Don't Save**)
2. 명령 프롬프트에서 바뀐 파일 확인
   ```bash
   cd C:\Projects\Bangkku
   git status
   ```
3. 테스트 때문에 바뀐 것만 되돌림
   ```bash
   git restore Packages/manifest.json Packages/packages-lock.json Assets/Settings/PC_Renderer.asset Assets/Settings/PC_RPAsset.asset
   git restore "Assets/XR/Settings/OpenXR Package Settings.asset"
   rmdir /s /q Assets\StreamingAssets
   del Assets\StreamingAssets.meta
   ```
4. `git status`를 다시 봄
   - `ProjectSettings/`가 남아 있으면 (Switch Platform, Development Build 등으로 바뀐 것): `git diff ProjectSettings`로 내용을 보고 기록한 뒤 `git restore ProjectSettings`
   - 변경이 하나도 없으면 끝
5. `Build\` 폴더는 커밋되지 않으니 남겨 둬도 됨 (시연용 exe로 다시 쓸 수 있음)

> 다음에 이 PC에서 다시 테스트할 때는 `git pull`로 최신 `dev`를 받은 뒤 06 문서 0.4부터 합니다.
