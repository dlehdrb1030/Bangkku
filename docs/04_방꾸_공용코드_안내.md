## 3. Core API (`Scripts/Core/`, 네임스페이스 `Bangkku.Core`)

`using Bangkku.Core;` 를 붙이고 사용합니다.

### 3.1 `Units`: 단위·좌표 변환

**규칙: 코드에 `0.001`, `1000` 같은 숫자를 직접 쓰지 않는다.** mm↔m 변환은 모두 `Units`를 거칩니다.

| 멤버 | 설명 |
|---|---|
| `MM_TO_M` = `0.001f` | mm → m 계수 |
| `M_TO_MM` = `1000f` | m → mm 계수 |
| `MmToM(int mm)`, `MmToM(float mm)` | mm → m |
| `MToMm(float m)` | m → mm **정수** (반올림). JSON에 저장할 때 사용 |
| `PlanToWorld(x, y, heightM = 0)` | 평면도 좌표(mm) → Unity 월드 좌표(m). 평면도 X → Unity X, 평면도 Y → Unity **-Z** |
| `PlanToWorld(int[] planMm, heightM = 0)` | JSON의 `[x, y]` 배열을 그대로 넣는 버전 |
| `WorldToPlan(Vector3)` | Unity 월드 좌표 → 평면도 좌표(mm 정수). 높이는 버림 |

```csharp
// 카탈로그 치수(mm) → BoxCollider 크기(m)
box.size = new Vector3(Units.MmToM(item.Size.W), Units.MmToM(item.Size.H), Units.MmToM(item.Size.D));
// 같은 것을 더 짧게: box.size = item.Size.ToMeters();  (4.1 참고)

// 스플랫 실측 크기와 비교
float errorM = Units.MmToM(item.SplatMeasuredSize.W - item.Size.W);
```

> ⚠️ 평면도 Y는 Unity **-Z**로 갑니다 (5장). 평면도 좌표를 Unity 좌표로 바꿀 때는 부호를 직접 계산하지 말고 **반드시 이 함수만** 쓰세요.

### 3.2 `Confidence`: 치수 신뢰도

```csharp
public enum Confidence { Measured, Drawing, Estimated }
```

| 값 | JSON 문자열 | 의미 | 판정 여유값 |
|---|---|---|---|
| `Measured` | `"measured"` | 줄자 실측 | 10mm |
| `Drawing` | `"drawing"` | 도면·상품 상세 치수 | 30mm |
| `Estimated` | `"estimated"` | 표준값으로 추정 | 100mm |

| 멤버 (`ConfidenceExtensions`) | 설명 |
|---|---|
| `confidence.MarginMm()` | 여유값 mm (10 / 30 / 100) |
| `confidence.MarginMeters()` | 여유값 m (0.01 / 0.03 / 0.1) |
| `confidence.ToJsonValue()` | JSON 문자열 (`"measured"` 등) |
| `ConfidenceExtensions.TryParse(string, out Confidence)` | 문자열 → enum. 알 수 없는 값이면 `false`, 결과는 `Estimated` |
| `ConfidenceExtensions.Default` | `Estimated`. **JSON에 값이 없을 때 기본값** (가장 보수적으로 판정) |

- JSON에 신뢰도를 **빼먹으면 `estimated`(100mm)로 처리**되어 판정이 보수적으로 됩니다. 실측했다면 꼭 `"measured"`를 적으세요.

### 3.3 `Layers`: 물리 Layer

**규칙: `LayerMask.NameToLayer("Wall")` 처럼 문자열로 쓰지 않고 이 상수만 쓴다.**

| 상수 | 값 | 마스크 상수 |
|---|---|---|
| `Layers.Wall` | 6 | `Layers.WallMask` |
| `Layers.Floor` | 7 | `Layers.FloorMask` |
| `Layers.Furniture` | 8 | `Layers.FurnitureMask` |
| `Layers.Fixture` | 9 | `Layers.FixtureMask` |
| | | `Layers.PlacementObstacleMask` = 벽 + 가구 + 고정설비 (겹침 판정 대상) |


## 4. Data 클래스 (`Scripts/Data/`)와 가구 인터페이스 (4.6)

- JSON 읽기·쓰기는 **Newtonsoft Json** (`JsonConvert`)만 씁니다. `JsonUtility`는 중첩 배열을 못 읽어서 쓰지 않습니다.
- 길이는 JSON 그대로 **mm 정수**로 들어 있습니다. m가 필요하면 `Units`로 바꿉니다.
- JSON 키는 클래스에 `[JsonProperty("키")]`로 명시되어 있어 **JSON 키 이름과 C# 이름이 달라도** 됩니다 (C#은 PascalCase).
- 모든 클래스에 `[Preserve]`가 붙어 있습니다. Android IL2CPP 빌드에서 코드 정리(stripping)로 Newtonsoft가 쓰는 필드가 지워지는 것을 막습니다. **필드를 추가할 때도 `[JsonProperty]`를 꼭 붙이세요.**

### 4.1 `CatalogData` (네임스페이스 `Bangkku.Furniture`) ← 팀원이 주로 쓰는 것

`catalog.json` (팀원 관리) 형식입니다. 전체개발계획 7.2와 같습니다.

```csharp
public class CatalogData { public List<CatalogItem> Items; }
```

**`CatalogItem` 필드**

| JSON 키 | C# 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| `id` | `Id` | string | 필수 | 에셋 ID, 소문자_번호 (`sofa_01`) |
| `name` | `Name` | string | 필수 | 표시 이름 (`2인 소파`) |
| `source` | `Source` | `FurnitureSource` | 필수 | `"scan"` / `"mesh"` / `"box"` |
| `prefab` | `Prefab` | string | scan, mesh | 프리팹 경로 (`Prefabs/Furniture/sofa_01`). box는 없음 → `null` |
| `size` | `Size` | `SizeMm` | 필수 | **판정 기준 치수** `{ "w", "d", "h" }` (mm) |
| `sizeConfidence` | `SizeConfidence` | `Confidence` | 권장 | 빼면 `estimated` |
| `splatMeasuredSize` | `SplatMeasuredSize` | `SizeMm` | scan | 스플랫에서 잰 치수. 없으면 `null` |
| `fitError` | `FitError` | float? | scan | 크기 보정 오차 비율 (`0.021` = 2.1%). 없으면 `null` |
| `unscannedFaces` | `UnscannedFaces` | List&lt;string&gt; | 선택 | 스캔 못 한 면 (`["back"]`). 없으면 빈 리스트 |
| `color` | `Color` | string | box | 박스 색 `"#RRGGBB"`. 없으면 `null` |

| 메서드 | 설명 |
|---|---|
| `item.Size.ToMeters()` | `Vector3(W, H, D)` m 단위. **Unity 축 순서(X=W, Y=H, Z=D)** 이고 `FurnitureItem.SizeMeters`, `BoxCollider.size`와 같은 순서 |
| `item.TryGetColor(out Color c)` | `color` 문자열 → Unity `Color`. 없거나 잘못된 값이면 `false` |

**치수 축 정리**

| JSON | 의미 | Unity 축 |
|---|---|---|
| `w` | 폭 | X |
| `d` | 깊이 | Z (가구 정면 = +Z) |
| `h` | 높이 | Y |

- BoxCollider: `size = item.Size.ToMeters()`, `center.y = 높이 / 2` (가구 원점 = 바닥면 중앙, 전체개발계획 8.1)

**`FurnitureFactory` 에서 읽는 예**

```csharp
using Bangkku.Furniture;
using Newtonsoft.Json;

CatalogData catalog;
try
{
    catalog = JsonConvert.DeserializeObject<CatalogData>(jsonText);
}
catch (JsonException e)
{
    // 알 수 없는 enum 값("source": "scna" 같은 오타)이나 형식 오류는 여기서 잡힌다
    Debug.LogError($"[방꾸] catalog.json 읽기 실패: {e.Message}");
    return;
}

foreach (CatalogItem item in catalog.Items)
{
    // item.Source 에 따라 3DGS / 메쉬 / 박스 생성 후
    // furnitureItem.Init(item);   ← 판정·상태 표시는 팀장 코드가 담당
}
```

- `"source"`, `"sizeConfidence"` 에 **정해진 값 외의 문자열(오타 포함)이 있으면 예외**가 납니다. 위처럼 `try`로 감싸 주세요.
- `prefab` 경로를 실제로 어떻게 불러올지(`Resources.Load`, 프리팹 목록 ScriptableObject 등)는 **`FurnitureFactory` 담당(팀원)이 정합니다.** `Resources.Load`를 쓰려면 프리팹이 `Resources` 폴더 아래 있어야 하니, 정해지면 이 문서와 7.2 예시 경로를 같이 맞춰 주세요.
- `CatalogItem`에 필드가 더 필요하면 **직접 고치지 말고 팀장에게 요청**하거나 PR로 올려 주세요. (Data는 공용, 변경 시 공지)

### 4.5 검증한 것

전체개발계획 7.1~7.3의 JSON 예시를 그대로 읽어서 확인했습니다 (15개 항목 통과).

### 4.6 `FurnitureItem`과 베이스 프리팹 (네임스페이스 `Bangkku.Placement`, 팀장) ← 팀원 가구 프리팹의 기준

`Scripts/Placement/FurnitureItem.cs`와 `Prefabs/FurnitureItem_Base.prefab`입니다 (전체개발계획 8.1, 8.2).
팀원의 가구 프리팹은 모두 **이 베이스 프리팹의 Prefab Variant**로 만듭니다.

**프리팹 구조**

```
FurnitureItem_Base (루트)   Layer = Furniture
│  Rigidbody                 isKinematic = true, useGravity = false
│  FurnitureItem             BoxCollider, LabelAnchor 연결됨
│  XRGrabInteractable        Kinematic, Track Rotation 끔, Throw on Detach 끔, Dynamic Attach 켬
├── Visual                   ← 팀원: 3DGS 렌더러 / 메쉬 / 박스를 이 아래에 넣음
├── Collider                 BoxCollider (판정용)
├── Outline                  ← 팀장: 박스 윤곽선 (3주차)
└── LabelAnchor              박스 윗면 중앙
```

**`FurnitureItem` 공개 API** (8.2와 같음, 굵은 것은 8.2에 없던 추가)

| 멤버 | 설명 |
|---|---|
| `ItemId` | catalog id |
| `SizeMeters` | 실측 W, H, D (m). Unity 축 X, Y, Z |
| `SizeConfidence` | 치수 신뢰도 |
| `BoxCollider` | 판정용 BoxCollider (`Collider` 자식) |
| `LabelAnchor` | 거리 라벨 위치 |
| `State` | `PlacementState.Free` / `Tight` / `Overlap`. 판정 코드(팀장)가 정함 |
| `MinGapMeters` | 가장 가까운 벽·가구까지 (m). 판정 전이면 `PositiveInfinity` |
| `Init(CatalogItem data)` | `FurnitureFactory`가 생성 직후 호출 |
| **`Data`** | `Init`으로 받은 `CatalogItem` (UI에서 이름 표시용) |
| **`PlacementChanged`** | `State`·`MinGapMeters`가 바뀔 때 이벤트 (윤곽선·라벨용) |

**`Init(item)`이 자동으로 하는 것**
- `ItemId`, `SizeMeters`(= `item.Size.ToMeters()`), `SizeConfidence`, 오브젝트 이름(= `item.Id`) 설정
- `Collider`의 BoxCollider를 **실측 치수로** 맞춤: `size = SizeMeters`, `center.y = 높이 / 2`
- `LabelAnchor`를 **박스 윗면 중앙**(`y = 높이`)으로 옮김

> 전체개발계획 8.1에는 Collider 크기와 LabelAnchor 위치를 팀원이 맞추도록 되어 있지만, **`Init`이 catalog 치수로 자동으로 맞춥니다.** 프리팹에서 직접 값을 넣을 필요가 없고, 넣어도 실행 시 `Init`이 덮어씁니다. (프리팹 미리보기용으로만 의미 있음)

**팀원: 가구 프리팹(Variant) 만드는 법**
1. `Tools > 방꾸 > FurnitureItem_Base 프리팹 생성`은 **팀장이 한 번만** 실행합니다. 이미 있으면 덮어쓰지 않습니다.
2. Project 창에서 `Assets/_Project/Prefabs/FurnitureItem_Base` 우클릭 → **Create > Prefab Variant**
3. 이름을 에셋 ID로 바꾸고 `Assets/_Project/Prefabs/Furniture/`로 옮김 (예: `sofa_01.prefab`)
4. Variant를 열고 **`Visual` 아래에** 3DGS 렌더러(또는 메쉬)를 넣음. 크기 보정(`SplatFitter`)도 `Visual` 쪽에서 함
5. **바꾸지 말 것**: 루트의 Layer·Rigidbody·`FurnitureItem`·`XRGrabInteractable`, `Collider`·`LabelAnchor` 자식의 위치·회전·스케일 (위치 0, 회전 0, 스케일 1이어야 판정 박스가 맞음. 어긋나면 `Init` 때 Console에 경고)
6. 가구를 선택하면 Scene 뷰에 **하늘색 박스**(판정 박스)가 보입니다. `Visual`이 이 박스에 맞게 들어가 있는지 확인

**`FurnitureFactory`에서 생성하는 예**

```csharp
GameObject go = Instantiate(prefab, position, Quaternion.identity);
var furniture = go.GetComponent<FurnitureItem>();
furniture.Init(item);   // CatalogItem
```

- 3DGS가 안 되는 가구(`source: "box"`)도 같은 베이스 프리팹으로 만들고 `Visual`에 박스 메쉬를 넣으면 됩니다.
- 판정(`State`, `MinGapMeters`)과 윤곽선·라벨은 팀장 코드(`PlacementValidator`, 3주차)가 담당합니다. 지금은 `State`가 항상 `Free`입니다.

## 5. ✅ 결정됨: 평면도 Y축 → Unity **-Z** (2026-11-03)

전체개발계획 5장 축 규칙을 **"평면도 X → Unity X, 평면도 Y → Unity -Z"** 로 바꿨습니다. (`Units.PlanToWorld`, `WorldToPlan` 반영, PR #1)

**이유**: 평면도 이미지는 **Y가 아래로** 커지고, Unity를 위에서 내려다보면(Top 뷰) **+Z가 위쪽**입니다. 예전 규칙(Y → Z)대로면 위아래가 뒤집혀 **방이 거울상(좌우 반전)** 이 됩니다.

```
평면도 이미지 (= 실제 집)     예전 규칙 Y → Z (거울상)     바뀐 규칙 Y → -Z
 ┌─[현관]─┬──────┐            ┌───────────────┐            ┌─[현관]─┬──────┐
 │        │ 욕실 │            │    발코니     │            │        │ 욕실 │
 │주방    └──────┤            ├───────────────┤            │주방    └──────┤
 │   거실/침실   │            │   거실/침실   │            │   거실/침실   │
 ├───────────────┤            │주방    ┌──────┤            ├───────────────┤
 │    발코니     │            │        │ 욕실 │            │    발코니     │
 └───────────────┘            └─[현관]─┴──────┘            └───────────────┘
```

- 현관에서 발코니를 바라볼 때 실제 집은 **주방이 오른쪽**인데, 예전 규칙은 왼쪽이 됩니다. 바뀐 규칙은 실제와 같습니다 (테스트로 확인).
- Unity 좌표로는 방이 **Z 0 ~ 음수** 범위에 생깁니다 (원룸 16형: Z 0 ~ -6.86m). 기능상 문제는 없습니다.
- 겹침·간격 **판정 숫자는 어느 규칙이든 같습니다** (거울상도 거리는 같음). 바뀐 것은 공간감·실제 집과의 비교입니다.
- 고정설비 `rotation`(도): 평면도에서 시계 방향 = Unity Y회전 + 방향으로 그대로 씁니다.

**팀원에게 미치는 영향**: 없습니다.
- 가구 자체(치수, +Z 정면, 바닥면 중앙 원점)는 가구 로컬 좌표라 영향이 없습니다.
- `layout.json`의 `position`은 평면도 좌표(mm)로 저장되므로 JSON 형식도 같습니다.
- 평면도 좌표 ↔ Unity 좌표는 직접 계산하지 말고 `Units.PlanToWorld` / `WorldToPlan`만 씁니다.
