### 1.3 새 작업 브랜치 만들기

```bash
git fetch origin
git switch dev
git pull --ff-only
git switch -c feature/hj-splat-first
```

- 11-08 전에 clone했다면 `git pull --ff-only`가 실패할 수 있습니다 (그날 커밋 기록을 다시 씀). 로컬 `dev`에 내 작업이 없으면 `git reset --hard origin/dev`로 맞춥니다 (04 문서 1.1).
- `hj` 브랜치의 테스트 파일이 필요하면 브랜치를 바꾸지 말고 파일만 꺼냅니다.
  ```bash
  git restore --source=origin/hj -- Models/office_chair_clean_unscaled.ply
  ```
  꺼낸 파일은 정리(SuperSplat) 후 이름을 바꿔 `Assets/StreamingAssets/Splats/`로 옮기고, `Models/` 폴더는 커밋하지 않습니다.

### 1.4 PR마다 브랜치 하나

앞 PR이 `dev`에 병합된 뒤, **최신 `dev`에서** 다음 브랜치를 땁니다.

| 순서 | 브랜치 (예) | 내용 |
|---|---|---|
| 1 | `feature/hj-splat-first` | 플러그인 v2.0.0 + URP 설정 + 가구 1개 + `Test_Splat.unity` |
| 2 | `feature/hj-catalog-factory` | `catalog.json`, `CatalogLoader`, `FurnitureFactory`, `SplatFitter` |
| 3 | `feature/hj-splat-furniture` | 나머지 3DGS 가구, 박스 가구 2~3개, 메쉬 가구 1개 |
| 4 | `feature/hj-perf` | `PerfRecorder`, 최적화한 스플랫 |
| 5 | `feature/hj-accuracy` | `AccuracyReport`, 정확도표 |

- 커밋 메시지: `feat:`, `fix:`, `docs:` (예: `feat: 3DGS 플러그인 v2.0.0 + desk_01`). 제목과 본문 사이에 빈 줄.
- PR은 `dev`로 (`main` 아님). 병합 방식은 **Create a merge commit**.
